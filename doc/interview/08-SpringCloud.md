# Spring Cloud 面试题

> 适用岗位：中高级 Java 后端。考察建议：先问「你们用的什么版本、什么组件组合、为什么」，用版本演进筛掉背旧资料的人；原理题沿追问链下探。

---

## 一、体系认知与版本演进（开场必问）

1. Spring Cloud Netflix（Eureka/Ribbon/Hystrix/Zuul）大面积停更后，Spring Cloud Alibaba 和 Spring Cloud 官方各自怎么补位？画出你们项目的组件选型全景图，并说明每个选型理由。
2. Spring Cloud（英文名）与 Spring Cloud Alibaba 版本兼容关系怎么维护（如 Hoxton 对应 2.2.x）？一次大版本升级（如 Spring Boot 2 → 3）你踩过哪些坑（javax → jakarta、组件废弃）？
3. Spring Cloud 与 Dubbo 的体系差异：一个偏 REST 生态、一个偏 RPC 二进制协议——什么场景你选哪条路线？Spring Cloud Alibaba 里 Dubbo 和 OpenFeign 混用的经历？

## 二、注册中心（必考）

4. Eureka 原理追问链：
   - AP 设计：自我保护机制（15 分钟内心跳低于 85% 不剔除）解决什么问题？代价是什么？
   - 三级缓存（readOnlyCacheMap / readOnly 与 renderRegistry / 客户端缓存）与多级缓存的一致性（30s），为什么设计成这样？
   - Eureka 2.x 为什么烂尾？服务感知延迟在 Eureka 上是固有的吗（客户端 30s + 只读缓存 30s + Ribbon 30s 叠加）？
5. Nacos 原理追问链：
   - AP（Distro 协议）与 CP（Raft）两种模式怎么选，临时实例 vs 持久实例的区别？
   - 1.x 的 UDP 推送 → 2.x gRPC 长连接推送解决了什么问题？为什么延迟从秒级降到毫秒级？
   - 心跳 + 连接状态双重健康检查的误判场景？优雅下线（主动注销 + 缓存刷新）怎么做到推空保护？
6. 对比选型：Eureka / Nacos / Consul / ZooKeeper 的 CAP、健康检查、推送时效、运维成本对比表。让你今天新项目选型，选谁，为什么？
7. 场景题：发布期间消费者拿到已下线实例导致调错，怎么系统性解决（优雅停机、主动下线、网关侧过滤、灰度池隔离）？

## 三、配置中心

8. Nacos 配置中心原理：长轮询（29.5s）机制的完整时序为什么是长轮询而不是长连接轮询或纯推送？配置变更的灰度发布、监听粒度（namespace/group/dataId）怎么设计多环境隔离？
9. 配置优先级、动态刷新原理（`@RefreshScope` 的 Bean 重建机制）？刷新失败 / 部分实例刷新失败的兜底？
10. Nacos vs Apollo 怎么选（发布审批、权限、审计、灰度能力维度）？敏感配置（数据库密码）的加密方案（Jasypt / KMS）？
11. 场景题：配置中心全挂了，怎么保证线上服务还能起、还能跑（本地快照 / cache-data / 启动容灾参数）？这个场景你们演练过吗？

## 四、RPC 与负载均衡

12. OpenFeign 原理追问链：
    - `@FeignClient` 接口怎么变成 HTTP 调用的（动态代理 → MethodHandler → 编码器 → 客户端）？
    - 默认客户端与 okhttp/HttpClient 的替换；连接池不配会发生什么（每请求建连）？
    - 超时体系（Feign 配置 / LoadBalancer / 网关 / Ribbon 旧版）的覆盖关系与坑；
    - 重试机制：Feign Retryer + LoadBalancer 重试叠加导致写请求重复执行的经典事故，你怎么配置避免？
13. Ribbon vs Spring Cloud LoadBalancer 的差异（轮询实现的 CAS 改进、`@LoadBalanced` 原理）；自定义负载均衡策略做过吗？
14. 服务调用的超时与降级全局策略：调用超时怎么定（P99 打底 + 留 buffer）？并发线程数隔离 vs 信号量隔离在 Feign 层怎么落地？
15. 场景题：Feign 接口偶发 `Read timed out`，给你排查树：网络 → 连接池 → GC 停顿 → 下游慢 → 重试叠加放大，逐层说怎么确认。

## 五、熔断、限流、降级（必考）

16. Hystrix 为什么被淘汰（线程池开销、维护停滞）？Sentinel 与 Resilience4j 的对比（规则中心 / 注解支持 / 热更新）？
17. Sentinel 原理追问链：
    - 滑动窗口统计结构（LeapArray）原理；QPS 限流三种策略（直接/关联/链路）什么场景用？
    - 熔断降级三策略（慢调用比例 / 异常比例 / 异常数）的触发与半开恢复机制；
    - 热点参数限流的实现（参数索引 + 桶）？集群限流的 token server 模式？
    - `@SentinelResource` 与 `blockHandler` / `fallback` 的区别（BlockException vs 业务异常）。
18. 降级开关体系设计：降级预案怎么分级、谁有权限开、怎么演练验证、怎么自动恢复？
19. 场景题：大促前压测，某核心接口在下游抖动时雪崩拖垮整个应用，讲完整的防护方案（超时收敛 → 熔断 → 降级兜底 → 线程隔离 → 预案开关）。

## 六、网关

20. Spring Cloud Gateway 原理追问链：
    - 基于 WebFlux/Netty 的反应式模型，为什么能单机扛高并发？什么情况反而更糟（阻塞调用、上游同步依赖）？
    - Route / Predicate / Filter 三件套；Global Filter 与 Gateway Filter 的区别与执行顺序（order）；
    - 动态路由怎么实现（监听 Nacos 配置刷新路由表）？你们网关的自定义 Filter 做过什么（鉴权、限流、灰度染色、日志）？
21. 网关限流怎么实现（内置 RequestRateLimiter + Redis Lua / Sentinel 网关流控）？网关层的熔断与下游应用层熔断怎么分工？
22. 灰度发布在网关层怎么落地：按 header/用户/比例路由到灰度泳道，链路染色（tag 全链路透传）怎么保证不串泳道？
23. 网关自身高可用：无状态多实例 + 上层 LB；网关成为单点瓶颈的容量信号（连接数、TLS、带宽）与应对（连接池前置、HTTP/2、卸载到 LB）。

## 七、可观测性与分布式链路

24. Sleuth/Micrometer Tracing 的 TraceId 透传机制；跨线程池丢 TraceId 的经典问题怎么解（装饰器/TtlMDC）？
25. SkyWalking / Zipkin / Jaeger 选型对比（探针侵入性、存储、UI、告警）；SkyWalking 的字节码增强原理（agent → Instrumentation → 插件）对性能的影响？
26. 全链路灰度、全链路压测（影子库/影子 topic）这类依赖「流量染色」的架构，你的实现思路？为什么全链路压测不能简单用预发环境模拟？

## 八、场景与架构题

27. 从 0 设计一套微服务基础设施：新业务 5 个服务上线，网关、注册配置、RPC、熔断、监控、发布规范——给出你的最小可用清单（不要过度设计的理由）。
28. 服务间依赖故障演练：故意挂掉一个下游，预期系统行为是什么？写一份演练 checklist（熔断触发、降级兜底、告警冒烟、恢复探测）。
29. 微服务拆分后接口 RT 普遍比单体高 20~50ms，什么原因（网络、序列化、鉴权链路、多跳）？哪些优化（本地缓存元数据、批量接口、并行编排、去掉冗余跳数）？
30. 反直觉题：什么项目你会建议**不上** Spring Cloud 这套全家桶（单体 + 模块化、直接用 K8s Service + 内部 LB 的路线）？两条路线的迁移成本对比？

## 附：评估要点

| 维度 | 权重 | 观察点 |
|---|---|---|
| 体系与选型 | 15% | 版本演进是否清楚、选型有理由而非"公司用的" |
| 注册中心/配置中心 | 20% | AP/CP、长轮询、推送机制讲到协议层 |
| RPC 与超时重试 | 20% | 覆盖关系、幂等事故、偶发超时排查树 |
| 熔断限流降级 | 25% | Sentinel 原理 + 预案体系 + 真实防护案例 |
| 网关与可观测 | 10% | 反应式模型、动态路由、链路染色 |
| 场景架构 | 10% | 最小可用意识、演练经验、反向选型判断 |

**判定要点**：
- **中级**：会用组件、能背「Eureka 是 AP、Nacos 支持双模」但讲不出机制。
- **高级**：能讲协议与源码级机制（长轮询时序、gRPC 推送、LeapArray），有超时重试幂等的真实事故案例。
- **资深**：有全套预案体系与演练经验，能做反向选型（何时不用全家桶），推动过组件升级或替换。
