# 服务熔断、限流、降级专项面试题

> 适用岗位：后端/架构方向。这三件事是稳定性体系的"三板斧"，面试常与线上事故结合出题。注意与 02（分布式与高可用）、08（Spring Cloud）中的相关题互为补充——本篇下探到算法与实现层。

---

## 一、限流（Rate Limiting）

### 算法层（必考）

1. 四种经典限流算法逐一追问链：
   - 固定窗口计数器：实现最简单，但**窗口边界突刺**问题怎么产生的（临界双倍流量）？什么场景可以接受？
   - 滑动窗口计数器：环形桶数组怎么实现（Sentinel 的 LeapArray）？桶数与统计精度的权衡；
   - 漏桶（Leaky Bucket）：恒定速率放行，适合整形流量；为什么它**无法应对突发**？
   - 令牌桶（Token Bucket）：预分配 + 突发能力；Guava RateLimiter 是什么桶（SmoothBursty / SmoothWarmingUp 的区别，预热限流什么场景用）；
   - 追问：漏桶和令牌桶的本质区别一句话说清（漏桶限的是"流出速率"，令牌桶限的是"平均流入速率 + 允许突发"）。
2. 单机限流实现层：
   - 手写一个并发安全的令牌桶（CAS 自旋 / synchronized 的取舍）；
   - Guava RateLimiter 的坑：它是单机的、acquire 会**阻塞当前线程**（tryAcquire 才是非阻塞）、不支持分布式；
   - Redis + Lua 实现分布式限流：令牌桶 / 滑动窗口（ZSet 版本）的脚本怎么写，为什么要用 Lua 而不是"get 后判断再 set"？
   - Redis 限流的性能瓶颈与容错：Redis 挂了限流怎么办（fail-open 还是 fail-close，怎么选）？
3. 分布式集群限流的进阶方案追问链：
   - 集中式计数（Redis）：所有请求打 Redis，性能上限与热点问题；
   - 配额分割（token server / 分片预分配）：Sentinel 集群限流的 token server 模式原理——客户端向 token server 申请额度，坏了怎么降级回本地限流；
   - 本地预估 + 全局校正（SWIM/自适应限流）：大流量下为什么"每实例限 总QPS/实例数"是错的（流量不均、实例数变化）？
4. 限流的位置与维度：
   - 接入层（Nginx limit_req / 网关）与应用层的分工；
   - 限流维度：全局 QPS、单接口、单用户、单 IP、单租户——热点参数限流的实现原理；
   - 并发数限流 vs QPS 限流的区别（慢调用下 QPS 限流为什么不够，信号量隔离的定位）。

### 实战层

5. 被限流的请求怎么处理：直接拒绝（快速失败）、排队等待（队列 + 超时）、降级响应——不同业务怎么选（下单 vs 查询）？返回什么状态码与提示（429 + Retry-After 的意义）？
6. 限流阈值怎么定：压测容量法（P99 达标时的最大吞吐）、经验系数法、自适应（TCP BBR 思想的 BBRSentinel：基于采样 RT 与最小 RT 推算）；
7. 场景题：
   - 大促峰值预估 10w QPS、系统容量 6w，链路上有网关 → 服务A → 服务B → DB，每一层的限流值怎么分配（逐层收敛 + 每层留 buffer 的理由）？
   - 一个 IP 刷接口，怎么在网关和应用层设计两级限流 + 黑名单，误伤 NAT 出口用户怎么办？

## 二、熔断（Circuit Breaking）

### 模式与原理（必考）

8. 熔断器模式追问链：
   - 三态模型：Closed → Open → Half-Open 的转换条件，画出状态机；
   - 为什么需要熔断：故障实例的"重试风暴 + 线程堆积 + 连锁雪崩"传导路径讲一遍；
   - 半开态的并发探测怎么控制（放多少请求试探、探测失败的回退）；
   - 断路器粒度：按服务、按接口、按实例、按"调用组"——粒度过细/过粗的代价。
9. 熔断判定策略追问链：
   - 异常比例、异常数、**慢调用比例**（RT 超阈值占比）分别适合什么故障（快失败 vs 慢调用堆积）？为什么慢调用更危险（线程池被拖死的速度）？
   - 统计窗口（滑窗时长、最小请求数 minRequestAmount）的意义：流量小时 1 次异常就熔断的误判怎么防？
   - 熔断时长怎么定（太短反复抖动、太长错过恢复）？探活与渐进恢复（半开逐步放量）。
10. 主流实现对比：
    - Hystrix（线程池隔离、滑动窗口、维护终止）为什么被淘汰；
    - Resilience4j（Ring BitBuffer、装饰器组合：CircuitBreaker/RateLimiter/Bulkhead/Retry/TimeLimiter）；
    - Sentinel（滑动窗口 LeapArray、规则中心热更、集群流控）；
    - Spring Cloud CircuitBreaker 抽象层；gRPC/RPC 框架内置熔断（Dubbo + Sentinel）；
    - 面试官问"自己手写一个简版断路器"：AtomicReference<CircuitState> + 计数器 + 时间窗口，核心并发点在哪（状态切换的 CAS、计数重置）？

### 实战层

11. 熔断对调用方的语义：熔断后抛什么（BlockException / 自定义异常）？调用方怎么区分"熔断失败"与"业务失败"（错误码设计、监控埋点）？
12. 熔断与重试的配合陷阱：重试会放大故障（重试风暴），为什么重试要有预算（retry budget，如最多 10% 流量重试）？指数退避 + 抖动（jitter）怎么实现？
13. 场景题：
    - 下游服务 GC 抖动导致 RT 偶发飙到 3s，上游线程池堆积拖垮全服务——写出你的完整防护链（超时收敛 → 慢调用熔断 → 半开恢复 → 下游限流自保）；
    - 熔断误触发（正常流量低峰被熔断）的原因与调参（最小请求数、统计窗口、按流量低谷单独立规则）；
    - 核心链路上某个"弱依赖"频繁熔断，你怎么判断该"加强依赖"还是"降级掉"（依赖分级评审的方法）。

## 三、降级（Degradation / Fallback）

### 策略层

14. 降级的分类追问链：
    - 读降级：返回缓存旧值 / 默认值 / 静态兜底页 / 精简字段（个性化推荐 → 热销榜）；
    - 写降级：异步化（先落 MQ/本地表后补）、限流写入、关闭非核心写入（关闭评价）；
    - 功能开关降级：非核心功能整体关闭（大促关闭退款入口）；
    - 读降级"返回旧值"的一致性风险（价格、库存场景的特殊红线）。
15. 降级开关的工程管理（必考）：
    - 开关存哪：配置中心（热更）+ 本地兜底（配置中心不可用时）；开关命名、归属、有效期；
    - 谁能开：审批与操作审计、双人复核；开错了怎么快速回滚；
    - 自动降级 vs 手动降级：自动（熔断联动、指标触发）的风险（误降级放大故障）与人工兜底；
    - 开关演练：大促前的降级预案演练怎么做（开开关 → 验证兜底表现 → 关闭恢复）。
16. 兜底数据从哪来：提前生成静态兜底文件、多级缓存的旧值、默认规则计算——兜底本身的可用性怎么保证（CDN、多副本、过期时间）？

### 实战层

17. 降级的业务协商：哪些功能可降是和业务方提前约定并评审过的（降级预案文档化），事故现场才不会吵——你怎么推动这件事落地？
18. 场景题：
    - 商品详情页依赖：库存服务、价格服务、推荐服务、评价服务，大促预案给每个依赖标注核心/可降级 + 降级后的用户表现；
    - 一次 P2 故障：推荐服务超时拖慢详情页，复盘里"为什么当时没降级"——从"无开关、有开关但没演练、开关开了但兜底数据过期"三个层面分别写出改进项；
    - 降级恢复的顺序设计（先恢复谁、怎么防止恢复瞬间的流量冲击——预热放量）。

## 四、隔离与综合（三板斧合体）

19. 隔离的三种手段追问链：
    - 线程池隔离 vs 信号量隔离：开销、适用场景（远程调用 vs 本地/纯内存）、Feign 下的配置演进；
    - 实例/集群隔离：核心服务与非核心服务物理隔离、单元化隔离；
    - 数据隔离：核心库与统计库分离、读写分离在故障时的用途。
20. 舱壁模式（Bulkhead）一句话解释 + 你们系统里哪些资源是"隔离"的（线程池、连接池、缓存实例、MQ topic、部署集群），漏了哪个会连环雪崩？
21. 综合场景题（压轴）：
    - 设计某电商核心下单链路的稳定性方案：预估峰值、给每段依赖（库存/券/支付/风控）配置限流值、熔断策略、降级预案，并说明故障传导路径上每一道防线拦什么；
    - 复盘题：一次雪崩（A 慢 → B 线程池满 → B 的所有接口超时 → 拖垮网关）发生后，你的改进项清单按"限流 / 熔断 / 降级 / 隔离 / 超时"五个维度各写至少一条；
    - 怎么验证这些预案有效：故障演练的注入点（延时/异常/满载）与每类预案的验收标准。
22. 开放题：限流、熔断、降级、隔离各自的"第一责任"是什么（保护自己 / 保护下游 / 保护体验 / 控制爆炸半径）？让你向新人只用四句话讲清四者的关系，你怎么讲？

## 附：评估要点

| 维度 | 权重 | 观察点 |
|---|---|---|
| 限流算法 | 30% | 四算法边界讲清、Redis+Lua/集群限流有实现层理解 |
| 熔断 | 30% | 状态机与判定策略、重试风暴、误判调参 |
| 降级 | 25% | 分类成体系、开关工程化（审批/演练/回滚） |
| 隔离与综合 | 15% | 爆炸半径意识、压轴题防线完整、有演练经验 |

**判定要点**：背得出"令牌桶、三态熔断"算中级以下；能讲清算法取舍、参数怎么定、有真实防护案例算高级；有预案体系（分级/审批/演练）、主导过雪崩复盘改进的算资深。
