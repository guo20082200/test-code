# Hive 与数据仓库面试题

> 适用岗位：大数据开发 / 数仓工程师。数仓建模与 Hive 优化是双核心，面数仓岗时建模权重应更高。

---

## 一、Hive 核心原理

1. Hive SQL 的执行链路：解析（Antlr）→ 语义分析 → 逻辑计划 → 优化（CBO/RBO，CBO 打开吗）→ 物理计划 → MR/Tez/Spark 执行——你们用什么引擎，怎么选的？
2. Hive 表的存储追问链：
   - 内部表 vs 外部表的真实区别与选型约定（drop 行为只是表象）；
   - 分区 vs 分桶：分区裁剪与桶裁剪分别怎么生效？分桶表在 sampling、bucket map join 里的用途；
   - 为什么大厂普遍规定"必须分区 + 帕累托分桶"？动态分区的坑（一天生成几千分区、小文件爆炸）怎么防（`hive.exec.max.dynamic.partitions`、预分区校验）？
3. 文件格式与压缩追问链：
   - TextFile / ORC / Parquet 深度对比（列存原理、索引：ORC 的 stripe 级 min/max、Bloom Filter）；
   - 行存 vs 列存的本质取舍（扫描列数 vs 点查/更新）；你们数仓 ODS→DWD 各层用什么格式，为什么？
   - 压缩编码：ZSTD/GZIP/Snappy 的取舍；ORC 的 dict encoding 与 RLE 什么时候失效？
4. join 的实现方式追问链：
   - Common Join（shuffle）的执行过程；
   - Map Join（广播小表）的触发条件与内存风险；
   - Bucket Map Join / SMB Join（分桶排序合并 join）的生效前提——你调过哪些让它真正生效？
5. 数据倾斜专项（Hive 版必考）：
   - `hive.groupby.skewindata` 的原理（两阶段随机打散）；`hive.optimize.skewjoin` 的区别；
   - count distinct 大表为什么慢（全部进一个 reducer）？改写方案（先 group 去重再 count、近似函数）；
   - join 倾斜：热点 key 打散、小表 join 大表的过滤下推；
   - 举一个你真实处理过的倾斜案例：现象 → 定位（日志/counter）→ 方案 → 前后耗时对比。

## 二、数据仓库建模（数仓岗核心）

6. 范式建模（3NF，Inmon）与维度建模（Kimball）的本质区别与适用场景？你们数仓为什么选维度建模？
7. 维度建模追问链：
   - 事实表四种类型（事务/周期快照/累积快照/无事实）各举业务例子；
   - 星型 vs 雪花模型的取舍（join 成本 vs 冗余维护）；
   - 维度退化是什么，为什么有用？
8. 缓慢变化维（SCD）必考：Type 1/2/3 的实现；拉链表追问链：
   - 拉链表的表结构、跑批逻辑（开链/闭链/全量比对）、查询某天全量快照的 SQL 怎么写；
   - 拉链表 vs 每日全量快照的存储与查询权衡；回溯修正（ late-arriving data）怎么处理？
9. 数仓分层架构追问链：
   - ODS/DWD/DWS/ADS（或你们自定义的层）各层职责与治理规范；为什么要分层，不分层的后果；
   - 每层的数据质量卡点放哪（ODS 原样保留 + DWD 清洗规则 + 各层 DQC 规则）；
   - 维度一致性：多个主题共用维表、口径统一（指标平台/口径字典）怎么落地？
10. 指标体系：原子指标、派生指标、修饰词的拆分方法；"同名不同义"的指标治理你做过吗，怎么收口的？
11. 元数据与血缘：解析 SQL 血缘的方案（Hive hook / Atlas / 自研解析）；血缘数据你们用来做什么（影响分析、下线治理、SLA 告警）？

## 三、Hive 优化与工程实战

12. SQL 调优清单（现场写 SQL 也可以考）：谓词下推是否总是生效、分区/桶裁剪验证、`mapjoin` hint、并行执行（`hive.exec.parallel`）、小文件合并（`concatenate` / insert overwrite 重写）、`order by` vs `sort by` vs `distribute by` vs `cluster by` 的精确区别。
13. HQL 转 MapReduce 的原理：group by 怎么MR化、distinct 的两个执行计划（倾斜与不倾斜）、join 的 key 分发——理解这个才能解释很多优化为什么有效。
14. Hive on Spark / on Tez 的调优差异：executor/driver 资源怎么定、shuffle 参数、动态分区插入的并发控制；你们怎么防止一个大 SQL 把 Spark 队列打爆？
15. 调度与依赖：Airflow/DolphinScheduler/DAG 中任务依赖与数据就绪（分区探活）怎么设计？任务失败重试、补数（backfill）与幂等怎么保证？
16. 数据质量体系（DQC）：完整性（分区量级波动）、准确性（主键唯一、值域、跨表一致性）的规则设计；告警的分级与误报治理。
17. 场景题：
    - 一个核心日报跑了 6 小时导致下游全部延误，给出系统性优化方案（SQL 改写、资源、依赖重构、拆分）；
    - 业务方要求"用户注册到首单的转化漏斗"报表，跨 3 张事实表、行为日志延迟到达，你的建模与计算方案？
    - 维表每天百万级变更，拉链表跑批 2 小时——怎么优化变更捕获（增量比对 vs 全量比对）？

## 附：评估要点

| 维度 | 权重 | 观察点 |
|---|---|---|
| Hive 原理与优化 | 35% | 执行计划/倾斜/文件格式讲到机制层，有前后耗时数据 |
| 数仓建模 | 40% | 分层规范、拉链表手写、指标口径治理方法论 |
| 工程实战 | 25% | 调度/质量/血缘成体系，有规模化治理案例 |

**判定要点**：只会写 SQL、说不出执行计划算中级以下；能把 HQL 翻译成 MR 讲清优化原理、拉链表现场手写算高级；数仓岗另需考察：建模方法论有自己观点、治理过脏指标、能主导分层规范落地。
